# Журнал решений

## Игровые данные и календарь

- **Время ротаций.** HoYoLAB возвращает дату без смещения. Для европейского сервера календарь применяет UTC+1 круглый год. Шестизначный ID может принадлежать опубликованной ротации Deadly Assault, поэтому для такого ID признаком выхода служит `live_begin`. [Модель даты](crates/rustverse/src/models/common.rs) · [Календарь](crates/nanoka/src/calendar.rs) · [Выбор сезона](crates/rustversebot/src/handlers.rs)
- **Сводки и анонсы.** После успешной загрузки обоих индексов планировщик целиком заменяет кэш расписания Nanoka. Детали сезона нужны в момент подготовки карточки к отправке. Итоговая сводка использует сезон своего контрольного окна, поскольку к этому времени в базе уже может появиться снимок следующего сезона. [Кэш расписания](crates/rustversebot/src/db.rs) · [Планировщик](crates/rustversebot/src/scheduler.rs)
- **Характеристики Deadly Assault.** Каждый режим получает собственные ставки. Для сложного режима `1002` таблица начинается с `1301`, если такой ключ есть. Старые ответы используют ключ типа зоны. HP округляется после сложения вкладов уровней, ATK берётся на выбранном уровне. Для очков различаются ставка последнего уровня и накопленная сумма. Пороги рангов заданы в API и сохраняются при масштабировании. [Расчёты](crates/nanoka/src/types.rs) · [Проверки на данных двух режимов](crates/nanoka/src/lib.rs)
- **Условия ранга в CLI.** Тип цели задаёт единицу измерения. Для испытания на время CLI переводит секунды в минуты и секунды, для очков показывает порог счёта, для родительского этапа выводит составные цели. [Вывод зон](crates/nanoka/src/main.rs)
- **Профиль HoYoLAB.** Вход с открытием браузера доступен до загрузки cookie. Имена агентов CLI запрашивает по UID игрока. При ошибке запроса и пустом кэше он может получить имена из списка собственного аккаунта. Для полного ростера используется отдельный список аватаров. Ник своего персонажа можно прочитать с карточки игры, для чужого UID источником служит Deadly Assault. [CLI](crates/rustverse/src/cli.rs)
- **Разовый запрос и регистрация.** Снимок привязан к UID. Только при обработке регистрации планировщик может дополнить ник в соответствующем чате. При регистрации бот сначала проверяет Deadly Assault, откуда можно получить ник. Запасная проверка через Shiyu подтверждает доступность данных. Клиент читает обе версии обёртки `hadal_info`, встречающиеся в ответах. [Опрос UID](crates/rustversebot/src/scheduler.rs) · [Проверка регистрации](crates/rustversebot/src/handlers.rs) · [Клиент HoYoLAB](crates/rustverse/src/client/zzz.rs)

## GachaBase и инструменты ассистента

- **Декодирование страниц.** В ответе SvelteKit поля и элементы массивов содержат индексы в общей таблице, даже если итоговое значение числовое. Специальное значение `undefined` декодер представляет как JSON null. Журнал изменений дочитывает следующую запись NDJSON, в которой разрешается отложенное значение. [Декодер](crates/rustverse_ai/src/gachabase.rs) · [Каталог](crates/rustverse_ai/src/catalog.rs) · [Журнал ревизий](crates/rustverse_ai/src/beta.rs)
- **Идентификация агентов и версий.** Канонический slug определяется по ID на выбранной ревизии. Для неполной записи возможен маршрут по ID. Совпадение отображаемых имён допускает разные ID, а родство форм подтверждает список владельца на той же ревизии. При сравнении веток исключаются `first_seen` и `last_updated`, поскольку GachaBase датирует ветки независимо. Манифест Nanoka содержит номера сборок без названия ветки. Поиск сохраняет доступный результат release при отсутствии беты. [Ревизии и формы](crates/rustverse_ai/src/beta.rs) · [Разрешение slug](crates/rustverse_ai/src/gachabase.rs) · [Поиск](crates/rustverse_ai/src/kit.rs)
- **Сравнение навыков.** Записи сопоставляются по ID, чтобы вставка навыка не сдвигала все последующие пары. В выражении CAL переменная уровня содержит сам уровень, а база записи `skill_data` соответствует первому уровню, поэтому число шагов роста равно `level - 1`. Небольшое скалярное изменение можно целиком передать на просмотр, а добавленного или удалённого агента — читать по разделам. [Сопоставление и формулы](crates/rustverse_ai/src/diff.rs) · [Группы изменений](crates/rustverse_ai/src/change_groups.rs) · [Индекс разделов](crates/rustverse_ai/src/gachabase.rs)
- **Страницы инструментов.** Компактная выдача сохраняет JSON Pointer на исходную запись. Краткие пассивные описания подходят для отбора напарников, а точные условия и числа можно проверить по ссылке. У рангов бывает общее описание при разных числовых характеристиках. При пагинации резервируется место для смещения и границ массива, крупное поле остаётся доступно отдельно. [Представления записей](crates/rustverse_ai/src/entry_view.rs)
- **Расчёты в Rhai.** Переменные ссылаются на общий JSON результата, иначе обращение к дочернему полю копировало бы весь ответ. Короткие числовые массивы доступны для суммирования и возврата. Имена привязок проверяются по правилам идентификаторов Rhai. Для истории `calls` предусмотрена своя переменная сверх бюджета скрипта. [Вычисления](crates/rustverse_ai/src/compute.rs) · [История результатов](crates/rustverse_ai/src/compute/history.rs)
- **Границы сжатия диалога.** Подпись и изображение собираются в один ход до подсчёта токенов. Сжатие охватывает законченный обмен или весь набор вызовов с результатами. Текущий вопрос сохраняется целиком. Последний завершённый обмен сжимается, если остальных мер недостаточно. В резюме прошлых визуальных ходов входят подпись и ответ, а точные ссылки на источники, версии и сезоны переносятся отдельно для последующих вычислений. [Сжатие истории](crates/rustverse_ai/src/context.rs)
- **Пределы провайдера.** Фактический предел может разойтись с локальным каталогом моделей. Запрос подсчёта тоже может оказаться слишком большим и получить отказ до возврата числа. Поэтому текст для сжатия делится по границам UTF-8 с повторной проверкой размера. [Подсчёт входа](crates/rustverse_ai/src/context.rs)
- **Завершение и проверка исследования.** Агенту доступны последовательные ходы для исследования. При сборке диспетчера увеличен предел рекурсии компилятора для проверки `Send` у цепочки асинхронных вызовов Nanoka. Проверяющая модель получает исходный запрос с вложениями, черновик и промежуточные результаты инструментов, чтобы сверить утверждения с использованными данными. В сообщениях об ошибках выводится категория сбоя, поскольку тело ответа провайдера может содержать учётные данные. [Цикл агента](crates/rustverse_ai/src/lib.rs)
- **Модель в кэше и учёт стоимости.** Ключ модели с исторической настройкой reasoning совместим с прежними отчётами, где сохранялся только ID модели. Для Decisions используются его собственная схема запроса и правила тарификации входа, включая обращения к кэшу. [Ключ модели](crates/rustverse_ai/src/model.rs) · [Стоимость](crates/rustverse_ai/src/routing.rs) · [Транспорт](crates/rustverse_ai/src/transport.rs)
- **Трассировка.** Блокирующий экспортёр выполняется на рабочем потоке SDK и использует тот же TLS-транспорт, что и Rig. Экспорт по одному span учитывает размер ходов с изображениями и предел OTLP в 64 МиБ. Фильтр пропускает события ассистента и GenAI-операции Rig, поскольку HTTP-клиенты могут записать полный URL или тело ответа. Обработчик инструментов принадлежит одному запуску и учитывает, что некорректный вызов может поступить ещё до создания span. [Зависимости](crates/rustverse_ai/Cargo.toml) · [Экспорт](crates/rustverse_ai/src/telemetry.rs) · [События инструментов](crates/rustverse_ai/src/telemetry/tools.rs)

## Telegram и хранение

- **Команды и темы.** Парсер передаёт команде всю строку аргументов, чтобы сохранить пробелы внутри запроса. После успешной обработки диспетчер убирает сообщение команды из чата. Отдельную ветку обсуждения внутри чата определяет тема форума Telegram, поскольку у обычного ответа в супергруппе также может быть ID цепочки. При изменении настроек админский API проверяет 52-битный диапазон ID чата. [Парсер](crates/rustversebot/src/main.rs) · [Диспетчер](crates/rustversebot/src/handlers.rs) · [Темы](crates/rustversebot/src/agent/telegram.rs) · [Админский API](crates/rustversebot/src/web/admin.rs)
- **Альбомы.** Telegram доставляет элементы отдельными сообщениями без признака последнего элемента. Обработчик возвращает управление диспетчеру, чтобы тот мог принять остальные фотографии. Бюджет вложений включает текущий запрос и изображения из выбранной ветки. [Медиагруппы](crates/rustversebot/src/prompt/media.rs)
- **Остановка и доставка.** Команда остановки и путь доставки забирают одну и ту же запись запроса. После остановки бот дожидается завершения локальных обновлений и генератора. Остановка действует и при гонке с публикацией зарезервированной задачи. Это исключает отправку результата после успешной отмены. [Отмена](crates/rustversebot/src/agent/cancel.rs) · [Очередь](crates/rustversebot/src/ai_jobs.rs)
- **Статус и итоговый ответ.** Перед следующей стадией бот дожидается последнего редактирования статуса. Закрытие канала прогресса завершает цикл обновлений. Если стадия и часть текста приходят вместе, первое редактирование показывает название стадии. В группе первая часть результата заменяет статус, последующие отправляются по порядку. Повтор касается отклонённой части. Удалённый статус можно заменить новым сообщением. Для черновиков используется прямой вызов Bot API, поскольку используемая версия teloxide предшествует `sendMessageDraft`. URL с токеном исключается из сообщений об ошибках. [Жизненный цикл запроса](crates/rustversebot/src/agent.rs) · [Доставка Telegram](crates/rustversebot/src/agent/telegram.rs)
- **Шаблоны и длина сообщения.** Суффикс файла определяет режим HTML и экранирование. При ошибке рендеринга обычный текст позволяет безопасно показать детали. Завершающий перевод строки обрабатывается при загрузке шаблона, чтобы оформление исходного файла сохраняло привычный текст сообщения. Лимит Telegram считается после разбора сущностей. В статусы попадают сокращённый вопрос и ограниченное по длине имя модели, итоговый ответ цитирует вопрос полностью. [Шаблоны](crates/rustversebot/src/templates.rs) · [Лимиты](crates/rustversebot/src/bot_templates.rs) · [Статус](crates/rustversebot/src/agent.rs)
- **Абзацы и разметка.** При разделении сообщения сохраняются позиция начала абзаца и стек HTML-сущностей. Это позволяет перенести целый абзац в следующую часть. При обработке списков учитываются пустые строки Markdown. Внутри блока кода вложенные сущности снимаются по требованиям Telegram. [Преобразование текста](crates/rustversebot/src/telegram_html.rs)
- **Доставка отчётов GachaBase.** Нулевой ID обозначает запись для всей ревизии, поскольку реальные ID агентов положительны. При обновлении бота чат может находиться посередине прежней поагентной рассылки. Уже доставленная часть учитывается при продолжении. Ручной запрос проверяет лимит всего диапазона до начала отправки, чтобы пользователь не получил часть отчётов перед отказом. [Подготовка и доставка](crates/rustversebot/src/beta.rs)
- **Миграции и ветки диалогов.** Старые строки без сведений о модели и инструкциях нельзя использовать как кэш современных отчётов. Каждая сохранившаяся ветка мигрирует в одной транзакции. После истечения срока жизни родителя его живые дочерние ветки становятся отдельными корнями в панели. Индексы ростеров версий 17 и 18 относились к выведенным из эксплуатации инструментам. [Миграции](crates/rustversebot/src/db.rs) · [Чтение веток](crates/rustversebot/src/db/admin.rs)
- **Лимит ручных ИИ-запросов.** Решение о доступе, строка аудита и запуск периода ожидания связаны одним SQL-оператором, чтобы параллельные запросы учитывались согласованно. [Проверка доступа в БД](crates/rustversebot/src/db.rs)
- **Промокоды.** Первый успешный опрос задаёт исходный набор для чата, включая случай пустого ответа. Доставку регистрируют после подтверждения Telegram. Парсер учитывает перечисления с неразрывными пробелами. При разбиении сообщения пустая строка шаблона отделяет заголовок и целые блоки кодов, чтобы награды оставались рядом со своим кодом. [Хранение](crates/rustversebot/src/db.rs) · [Разбор и отправка](crates/rustversebot/src/promocodes.rs)

## Изображения и сборка

- **Ресурсы карточки.** Личная карточка Shiyu берёт имя босса из соответствующего сезона. Имена загруженных файлов совпадают с последним сегментом URL, который использует шаблон. В общий кэш публикуется завершённая загрузка. Ответ 404 допустим на стадии подготовки, поскольку JSON содержит и неиспользуемые изображения. Typst сообщит об ошибке, если запрошенного шаблоном файла действительно нет. Для сезонных страниц шириной 20 см используется масштаб рендеринга, при котором ширина уже превышает 2560 пикселей. [Подготовка и рендеринг](crates/rustverse_images/src/lib.rs) · [Карточка Shiyu](crates/rustverse_images/individual_shiyu.typ)
- **Инструменты сборки.** Локальный скрипт добавляет каталог бинарников Cargo в PATH, поскольку на macOS он может отсутствовать. В Nix сборка зависимостей использует `cp` без наследования режима исходного файла. Иначе повторное копирование привязок libsql-ffi сталкивается с копией только для чтения. При установке самого бота используется штатный `cp`, чтобы итоговый файл сохранил право на выполнение. [Локальный запуск](dev/beta) · [Сборка Nix](flake.nix)
